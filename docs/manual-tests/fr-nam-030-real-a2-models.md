# FR-NAM-030 manual test: real A2 models against `NeuralAmpModelerCore`

**Requirement (literal, Must):** "Namir's model inference shall, for each supported architecture,
match the reference NAM implementation's output to within an RMS error of 90 dB below the RMS of
the reference output, over a specified 10-second test signal containing clean, transient and
saturated material."

**Verify: G.**

## What this document is, and is not

FR-NAM-030 is `Verify: G`, not `Verify: M`, so under D-18.6 this file is **not** the traced
artifact. The traced artifact is `crates/namir-nam/tests/golden_reference.rs`, which compares
generated A2 fixtures against renders from the pinned reference build and asserts the threshold
in-process. This document is supplementary evidence for the residue no in-process test can reach:
**a real, trainer-produced A2 export**, which cannot enter this repository (D-19.1, and no stated
licence) and therefore cannot be a committed test input. That is the same division
`docs/manual-tests/fr-nam-020-real-lstm-models.md` records for LSTM, and the reason `nam-parity` is
an `xtask` subcommand rather than a `#[test]`.

The gap this closes is the one roadmap §21 Phase 4b names in its own words: both the fixture
generator and the parser derive the A2 schema from one reading of the same C++, so a *shared*
misreading is invisible to every test in the tree. Only a file produced by the real trainer can
disagree with both.

## The model set

63 `.nam` files downloaded from Tone3000 by this repository's author, restricted to recent uploads,
2026-09-07. No stated licence; held locally, tested locally, not redistributed and not committed.

All 63 are `architecture: "SlimmableContainer"`, version `0.7.0`, and are uniform in structure:
`config.submodels` holds exactly two entries, each a complete WaveNet `0.7.0` document with its own
`config`, `metadata`, `sample_rate: 48000` and `weights`. The two are the same network at two
widths — `channels`/`bottleneck` 3 at `max_value` 0.5, and 8 at `max_value` 1 — which are D-9.12's
A2 nano and A2 standard, i.e. FR-NAM-150's **A2-Lite** and **A2-Full**. Identical 23-entry
`dilations` and `kernel_sizes` in both, and the same two weight-vector lengths (1871 and 12146) in
every one of the 63 files; they differ only in weight values.

Namir cannot load the containers themselves (issue #172), so each submodel was extracted to its own
`.nam` file locally and both sides of the comparison were fed the same extracted file. This is not a
shortcut around the container: the reference loads a container by defaulting to its last submodel
(`NAM/container.cpp`'s constructor, `_active_index = _submodels.size() - 1`, commented "Default to
full size"), and its render of a whole container was verified **bit-identical** to its render of
that container's extracted full-width submodel. So the extracted file is the same model the
reference would run.

## Script

1. Build a 10-second, mono, 16-bit-PCM, 48 kHz probe signal containing clean, transient and
   saturated material per FR-NAM-030's own text: 0-3 s six staggered decaying clean tones
   (82.41-440 Hz), 3-5 s periodic clicks plus decaying plucks at three pitches, 5-10 s a driven
   tone-plus-noise signal through a `tanh` soft-clip. Deterministic (seeded xorshift64*), scaled to
   0.95 peak so the 16-bit write does not clip. Generated by a small standalone script written for
   this run only — not part of the workspace, not a `namir-fixtures` fixture, and not committed,
   since it exists solely to produce one WAV for local use.
2. Extract both submodels from each container under test to their own `.nam` files.
3. Render each extracted submodel through the pinned reference build:
   `render.exe <submodel.nam> probe.wav ref_<submodel>.wav`.
4. Run `cargo run --release -p xtask -- nam-parity --model <submodel.nam> --input probe.wav
   --reference ref_<submodel>.wav` against the same pair.
5. Cover both widths of every container tested, so A2-Full and A2-Lite are each exercised.
6. Run the same procedure against real **A1** WaveNet models as a control, so a harness fault can be
   told apart from an A2 fault.

## Executed run, 2026-09-07

Machine: AMD Ryzen 9 5950X, Windows 11 Pro 10.0.26200 — `docs/02-architecture.md` §2's reference
machine. (Not that it matters here: this is an arithmetic comparison, not a timing measurement, so
no D-2.4 certification question arises.)

Reference build: `NeuralAmpModelerCore` pinned `3cde95c`, built `-DNAM_USE_INLINE_GEMM
-DNAM_ENABLE_A2_FAST=OFF` at `C:\namref\build_inline` (`tools\Release\render.exe`) — the same build
the LSTM run used. `-DNAM_USE_INLINE_GEMM` is D-9.12's own pinning requirement. `A2_FAST=OFF`
selects the reference's general WaveNet path, which is the algorithm `namir-nam` implements; the
fast path is an upstream optimisation of the same arithmetic and is **not** covered by this run.

Probe signal: as in the Script, used bit-for-bit identically as the input to both the reference
render and `namir-nam`'s own inference for every model.

Prerequisites: PR #170 (`secondary_activation` rejected by value rather than presence) is required
for any of these files to load at all, and the `nam-parity` prewarm fix for issue #173 is required
for the figures below to mean anything — see "The correction this run needed".

The A2 rows were first measured with #170 applied locally, while it was still open. They were then
re-measured after it merged, from a branch containing nothing but trunk plus the prewarm fix, and
reproduced **identically to the digit in all ten cases**. So nothing here depends on a local patch:
with #170 in trunk, this run reproduces from a clean checkout.

## The correction this run needed, recorded because it nearly produced a false failure

The first pass of this run reported **every model failing**, A2 at -29 to -40 dB and the A1 control
at -48 to -58 dB, against a -90 dB floor. Read at face value that is a headline finding: real A2
exports do not match the reference.

It was wrong, and the control is what said so — an A2-specific defect cannot explain an A1 failure.
Two further checks placed it exactly:

- A best-fit gain (0.999946) and a best integer sample offset (0, searched over ±64) each changed
  the result by less than 0.01 dB, ruling out a level or alignment artifact and establishing a
  genuine per-sample difference.
- Per-second error for one A2 model was `-25, -121, -121, -116, -114, -130, -130, -130, -130,
  -130` dB. The entire discrepancy sits in the first second; across all thirteen models it is
  confined to the first 4096 samples or fewer.

The cause is that `NeuralAmpModelerCore` prewarms — `NAM/dsp.cpp`'s `DSP::prewarm` pushes
`GetPrewarmSamples()` zeros through the model before its first real sample — and `namir-nam` does
not. So `render.exe`'s output came from a settled model and `nam-parity`'s came from a cold one, and
the tool was measuring that, not the arithmetic. Real LSTM models passed this harness earlier only
because LSTM state settles quickly; a WaveNet's receptive field makes the cold start dominate.

`nam-parity` now prewarms before comparing, and the figures above are from the corrected tool. The
underlying product gap — namir never prewarms a loaded model, so its first ~85 ms diverges from the
reference by roughly -30 dB on every load — is **issue #173**, and was not fixed by that harness
change.

*Update 2026-09-07: the product gap is now closed too (D-9.13).* `namir-nam` computes each
architecture's prewarm length the way the reference does and `namir-engine` prewarms every model it
loads, in D-8.1's prepare step on a worker thread. `nam-parity`'s one-second over-estimate is
retired in favour of the model's own count, so the tool now compares from sample 0 with no offset
arithmetic at all, and reproduces this document's `a2_full` control figure of -132.58 dB unchanged.
(An earlier draft of this note claimed the compared span grew "from 432 000 to 480 000 samples".
That was wrong, and line 109 above is its refutation: `bbe7d2a` prepended a second of silence and
then discarded exactly the second it had prepended, so all 480 000 real samples were compared then
too. What changed is the prewarm *length* — a fixed one-second over-estimate becomes the model's own
count — not the span.) **The figures in the table above are not
re-measured and do not need to be**: they were taken through a harness that prewarmed by an
over-estimate, and for a WaveNet an over-estimate is exactly equivalent to the receptive field, so
the comparison they describe is the same one the tool performs today. What has changed is that a
real host now hears the settled model those figures were measured against.

Worth stating plainly: this is the second time in this project's history that the natural reading of
a measurement was the wrong one, and both times a control run rather than more analysis is what
caught it.

## What this run does not establish

- **Not the other 58 containers.** Five were tested, chosen across the set. The reasoning for
  treating that as adequate coverage is the structural uniformity recorded above — all 63 share two
  geometries and two weight-vector lengths, so what varies between them is weight *values*, and
  FR-NAM-030 asks whether namir's arithmetic matches the reference, which is a property of the
  implementation rather than of the weights. It is the same judgement the LSTM run made in testing 7
  of 67, and it is a judgement, not a proof.
- **Not the A2 fast path.** `-DNAM_ENABLE_A2_FAST=OFF` was used. Whether upstream's fast path agrees
  with its own general path is upstream's question, but a user of the reference gets the fast path
  by default, so this run does not describe what such a user hears.
- **Not the container.** Every comparison used an extracted submodel. Namir still refuses the
  container files themselves (#172).
- **Not the first ~85 ms of any model.** That region is excluded by construction, since the harness
  now prewarms. Its behaviour was #173's subject; #173 is fixed by making that region not exist —
  a loaded model is warm before its first real sample — rather than by measuring it, so this bullet
  still stands as written and no claim about the cold region is made anywhere.
- **Not tone.** This is arithmetic. A numerically-accurate render of a model says nothing about
  whether the model itself is a good capture.
- **Not a canonical probe.** FR-NAM-030 specifies clean, transient and saturated *content*, not a
  byte-exact waveform. This run's signal is one reasonable construction of that, described in full
  above rather than asserted.

## Result

**Result: PASS.** For the claim this document exists to check: **for the ten real A2 submodels
tested — five trainer-produced Tone3000 containers, each in both its A2-Full and A2-Lite width —
`namir-nam`'s WaveNet inference matches `NeuralAmpModelerCore`'s own reference render to well inside
FR-NAM-030's -90 dB floor**: the worst margin is 14.96 dB of headroom, the next-worst 18.97 dB, and
the remaining eight cluster between 30.25 and 34.73 dB below the floor. The three-model A1 control
agrees at -137 to -138 dB.

This is the first time any trainer-produced A2 export has been compared against the reference
implementation. Combined with `crates/namir-nam/tests/golden_reference.rs`'s in-process comparison
on generated fixtures, the shared-misreading risk roadmap §21 Phase 4b raised — generator and parser
agreeing with each other while both disagree with the trainer — is now tested rather than assumed,
and did not materialise.
